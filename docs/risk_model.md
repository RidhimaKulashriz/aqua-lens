# Risk model

The numeric risk score is deterministic and unit-tested. The narrative
text that accompanies it is generated by Gemini 2.5 Flash from the same
inputs but can never override the numeric output.

## Numeric scoring

Implementation: [`backend/app/services/risk_model.py`](../backend/app/services/risk_model.py).

### Step 1 — Normalise each contributing factor

Each factor is mapped from its physical range into `[0, 1]` using
`normalize(value, low, high)`:

| Factor | Source | Range mapped to `[0, 1]` |
| --- | --- | --- |
| NDCI (chlorophyll proxy) | masked-mean NDCI | `[-0.1, 0.5]` |
| NDTI (turbidity) | masked-mean NDTI | `[-0.2, 0.6]` |
| NDVI shoreline stress | masked-mean NDVI | `[0.0, 0.6]` |
| MNDWI water-signal floor | `1 − normalize(MNDWI)` | `[0, 0.5]` |
| NDWI water-signal floor | `1 − normalize(NDWI)` | `[0, 0.5]` |

The “water-signal floor” terms reward a strong water mask; weak water
signals penalise confidence in the other indices.

### Step 2 — Weighted sum

```
base_score =
    0.40 * normalise(NDCI)
  + 0.25 * normalise(NDTI)
  + 0.10 * normalise(shore_NDVI)
  + 0.10 * mndwi_floor_penalty
  + 0.15 * ndwi_floor_penalty
```

The weights are module constants and sum to 1.0.

### Step 3 — Evidence bonus

If at least one field-evidence record is present, the latest one is
folded in as a bounded bonus (`max 0.5`):

| Driver | Weight | Cap |
| --- | --- | --- |
| Algae visible | +0.20 | — |
| Suspicious water colour (green/brown/yellow/red/black) | +0.10 | — |
| Suspicious odour (fishy/rotten/chemical/sewage/musty) | +0.10 | — |
| Dead fish | +0.05 per fish | 0.20 |
| Public complaints | +0.04 per complaint | 0.12 |
| Recent rainfall | +0.03 per 10 mm | 0.10 |

### Step 4 — Clamp and bucket

```
final = clamp(base_score + evidence_bonus, 0, 1)
level = bucket(final, { <0.33 → low, <0.66 → medium, else → high })
```

### Step 5 — Urgency

| Inputs | Urgency |
| --- | --- |
| HIGH + severe field signal (algae OR dead_fish ≥ 5 OR complaints ≥ 3) | `immediate` |
| HIGH | `elevated` |
| MEDIUM + severe field signal | `elevated` |
| MEDIUM | `routine` |
| LOW + severe field signal | `elevated` |
| LOW | `routine` |

## LLM narrative

Implementation:
[`backend/app/services/reasoning.py`](../backend/app/services/reasoning.py)
plus the prompt template
[`backend/app/services/prompts/reasoning.j2`](../backend/app/services/prompts/reasoning.j2).

The model receives a structured JSON dump of the inputs:

- water body name, centroid, area
- numeric risk score, level, urgency, and per-driver contributors
- every spectral index with value, interpretation, bands, sample count
- every evidence record

The system prompt forbids:
- Inventing measurements not present in the JSON.
- Changing the risk level or urgency.
- Claims of toxin detection, public-safety guarantees, or certified results.

Output is constrained by both `response_mime_type="application/json"`
and an explicit `response_schema` enforcing three string fields:
`recommendation`, `reasoning`, `limitations`.

If parsing or validation fails, AquaLens retries once with a stricter
"return only the JSON object" instruction. A second failure raises;
the session goes to `failed` status with the error message attached.

## Why hybrid

A deterministic numeric model is the only way to keep risk levels
explainable and auditable. A pure LLM-derived score would drift between
runs and be impossible to test against future regressions. But a pure
deterministic narrative is dry and rarely contextualises the evidence
well. Separating *what* (numeric model) from *why* (LLM) gets us both.
